# Vector Database — Architecture & Ingestion Guide

This project uses a **hybrid vector store** combining FAISS (dense semantic search) and BM25 (sparse keyword search) for highly accurate retrieval in the RAG pipeline.

---

## 📌 Why Hybrid Search?

| Method | Strength |
|---|---|
| **FAISS** (Dense) | Finds semantically similar text even with different phrasing |
| **BM25** (Sparse) | Finds exact keyword matches — great for names, codes, numbers |
| **Combined** | Best of both — high recall AND high precision |

---

## 🗄️ Storage Layout

```
app/database/vectordb/
├── ultrarag_faiss.index      ← FAISS dense index (auto-generated by ingest.py)
├── ultrarag_bm25.pkl         ← BM25 sparse index (auto-generated by ingest.py)
└── chroma/                   ← ChromaDB (fallback, auto-generated)

data/chunks/
├── unified_vectors.json      ← Source: pre-computed chunks + embeddings (committed to git)
└── corpus_ultrarag.jsonl     ← Generated: UltraRAG corpus (auto-generated by ingest.py)
```

> **Note:** Only `unified_vectors.json` is committed to Git.  
> All `.index`, `.pkl`, `.jsonl` files are auto-regenerated by `python scripts/ingest.py`.

---

## 🚀 Data Sources

The vector database is built from three sources:

### 1️⃣ Web-Scraped College Data
- **Source:** `data/scraped_data/outputs/*.json` (~97 files)
- **Content:** Structured JSON from 130 TKRCET website pages
- **Ingestion:** Chunked into 500-char segments with 100-char overlap

### 2️⃣ FAQ Dataset
- **Source:** `data/rawdata/faq_rows.json`
- **Content:** 300+ curated Q&A pairs about the college
- **Strategy:** Each FAQ stored as a single chunk (no splitting needed)

### 3️⃣ Knowledge Base
- **Source:** `data/knowledge_base.json`
- **Content:** Manually curated facts, key personnel, NAAC grade, etc.

---

## 🧠 Embedding Model

**Model:** `all-MiniLM-L6-v2` (SentenceTransformers)  
**Dimensions:** 384  
**Why:** Fast, lightweight, and excellent for semantic similarity at short-to-medium text lengths.

## 🔄 Ingestion Pipeline

```
data/scraped_data/outputs/*.json
data/rawdata/faq_rows.json
data/knowledge_base.json
         ↓
   scripts/ingest.py
         ↓
  unified_vectors.json  ──→  FAISS index (.index)
                        ──→  BM25 index (.pkl)
                        ──→  UltraRAG corpus (.jsonl)
```

### Run Ingestion (one-time setup):
```powershell
python scripts/ingest.py
```

---

## 🔍 Retrieval at Query Time

When a user sends a query, `ultra_rag.py`:

1. **Dense search** — FAISS finds top-K semantically similar chunks
2. **Sparse search** — BM25 finds top-K keyword-matching chunks
3. **Merge & Deduplicate** — Results are combined and deduplicated
4. **Cross-encoder Rerank** — `cross-encoder/ms-marco-MiniLM-L-6-v2` re-scores and sorts the merged results
5. **Generation** — Top chunks are passed to **Ollama** (`llama3.2:3b`) as context to generate the final response.

## 🔄 Refreshing the Data

To update the knowledge base after new scraping:

```powershell
# Step 1: Re-scrape (only needed when website updates)
python scripts/tkrcet_scraper.py

# Step 2: Rebuild the vector DB
python scripts/ingest.py
```
